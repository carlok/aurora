# Aurora Globe 3D

A 3D Earth and aurora viewer built with **WebAssembly/AssemblyScript** and **WebGL**, designed to run entirely in the browser with public data.

It shows:

- a high-resolution Earth globe;
- the OVATION auroral oval with an observed and forecast Kp timeline;
- aurora modelled as a layered 3D volume;
- IGRF-14 magnetic field lines rendered as 3D tubes;
- the Sun and Moon using real geocentric ephemerides and true scale;
- Sun–Earth and Moon–Earth guide lines;
- a modelled solar wind veil;
- rotation, pan, zoom and cursor-centred zoom;
- toggles for magnetic field lines and the solar wind veil;
- an Earth-lock toggle that freezes the globe while the time slider moves the celestial frame.

> No API key is required. Space-weather data is loaded directly from public NOAA/NASA services.

## Tech stack

- **AssemblyScript 0.28** → compiles to WebAssembly
- **WebAssembly** → geometry, matrices, field calculations, Kp interpolation and aurora texture generation
- **WebGL 1.0 + GLSL ES** → Earth, aurora, celestial bodies, field lines and solar wind rendering
- **JavaScript ES modules** → browser orchestration, WebGL, events and UI
- **Canvas 2D + TopoJSON** → Earth texture generated from Natural Earth data
- **HTML5 + CSS** → user interface and HUD
- **Node.js** → local static server
- **Astronomy Engine 2.1.19** (MIT) → geocentric Sun/Moon ephemerides
- **IGRF-14** → internal geomagnetic field model
- **world-atlas / Natural Earth** → geographic data for the Earth texture

No frontend framework, bundler or database is used.

## Local setup

Requirements:

- **Node.js 20 or newer**
- npm
- a browser with WebGL enabled

```bash
git clone <REPOSITORY_URL>
cd aurora-globe-3d

npm ci
npm run asbuild
npm test
npm start
```

Open:

```text
http://localhost:8081/
```

`npm run asbuild` generates the files in `build/`, which are required to load the Wasm module. The `build/` directory is generated and is not committed to Git.

Custom port:

```bash
PORT=8082 npm start
```

The local server only serves:

- `index.html`
- `build/`
- `vendor/`
- `/healthz`

## Tests

After building:

```bash
npm test
```

The tests verify the OVATION grid dimensions, aurora texture resolution and sphere geometry.

## Public data sources

| Data | Source | Use | URL |
|---|---|---|---|
| OVATION auroral oval | NOAA SWPC | Aurora shape | `https://services.swpc.noaa.gov/json/ovation_aurora_latest.json` |
| Observed and forecast Kp | NOAA SWPC | Timeline and aurora intensity | `https://services.swpc.noaa.gov/products/noaa-planetary-k-index-forecast.json` |
| Daily geomagnetic indices | NOAA SWPC | Historical Kp | `https://services.swpc.noaa.gov/text/daily-geomagnetic-indices.txt` |
| 27-day outlook | NOAA SWPC | Kp forecast | `https://services.swpc.noaa.gov/text/27-day-outlook.txt` |
| 50m land topology | Natural Earth / world-atlas | Earth texture | `https://cdn.jsdelivr.net/npm/world-atlas@2/land-50m.json` |
| 110m land fallback | Natural Earth / world-atlas | Earth texture fallback | `https://cdn.jsdelivr.net/npm/world-atlas@2/land-110m.json` |
| Internal magnetic field | IGRF-14, IAGA/NOAA | Magnetic field lines | `https://www.ngdc.noaa.gov/IAGA/vmod/igrf.html` |
| Sun/Moon ephemerides | Astronomy Engine | Position, distance, size | `https://github.com/cosinekitty/astronomy` |

### Data notes

- **OVATION** is a two-dimensional auroral probability model. The 90–220 km altitude profile is modelled, not a 3D observation.
- The **IGRF-14 field lines** in `vendor/fieldlines.json` are precomputed for epoch **2026-11-17**. IGRF describes the internal field and changes slowly; it is not an external magnetospheric field.
- The **solar wind veil** is an illustrative potential-flow model around a magnetopause-sized obstacle, with intensity driven by Kp. It is **not an MHD simulation** and does not use a live 3D solar wind feed.
- The Sun and Moon use real distances and radii (1 unit = 6371 km). The **MOON/SUN** buttons frame them; at true scale they appear small.
- Dates in the future are **forecast**, not observations.

## Static deployment

For static hosting, deploy `index.html`, `build/` and `vendor/`. Make sure `.wasm` files are served with `Content-Type: application/wasm`. The included server is for local development only; it does not expose source files or `node_modules`.
